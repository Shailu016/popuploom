## 2. Merge and deploy

Merging to `main` and pushing **is** the deploy. Pick one:

- Through GitHub: push the branch, open a pull request into `main`, review, merge.
- Locally: `git checkout main`, `git merge --no-ff template-premium-refresh`, `git push origin main`.

Then watch the **Test and deploy to Cloudflare** run in GitHub Actions. It runs the
security scan, all three suites, deploys, and checks live health. If any test
step fails, nothing is deployed.

## Cloudflare resource names (not changed)

The Worker service and the D1 database keep the names they were created with (`name` and `database_name` in `wrangler.toml`). Renaming them means creating new resources, re-adding every secret (`JWT_SECRET`, `RESEND_API_KEY`) and migrating the live database, and the names are never visible to visitors. If you still want them renamed, do it as a separate planned migration with a backup and a maintenance window.

After the deploy you can also remove the old workers.dev origin from the Google OAuth client's Authorized JavaScript origins.

## Rollback

Revert the merge commit on `main` and push; CI redeploys the previous build.

Caution: once 1.2.0 is live, new install snippets point at `/embed/1.2.0/`. A
plain revert would remove that path and break those sites. When rolling back,
keep `embed-releases/` and the 1.2.0 build entries, or restore them at once.
`/embed/1.1.0/` is identical in both builds, so existing customers are never
affected by a rollback.
