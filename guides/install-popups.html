How to add a popup to your website

Last product check: 5 November 2026. Product screenshots in this guide were captured from the actual PopupLoom build. Platform-specific caveats were checked against the official documentation linked below; a live site on every platform plan was not available for this review.

The installation model

PopupLoom separates the design from the installation. A saved popup gets a permanent widget id. Your website contains two short lines: a div with that id and the shared runtime script. The visitor's browser fetches the live configuration from PopupLoom, so edits you save in the studio reach installed copies without replacing the snippet.

You need permission to add custom HTML or theme code to the site. The site must be able to load https://popuploom.com/popuploom.js unless you deliberately self-host that file. A popup placed inside an iframe cannot draw outside that iframe.

1. Choose or write the popup

Browse the template catalog or start from a blank design in the studio. Templates are editable examples, not live offers. Replace any sample discount, stock, prize, points, email/SMS/PDF delivery, guarantee or security claim with the website owner's real terms. The editor does not send marketing email, SMS, PDFs or calendar invitations by itself.

Media fields take URLs. Use an image URL you control, or a YouTube/Vimeo URL for the video block. The runtime does not upload files for you.

2. Sign in and save

Create an account or sign in. A guest can design and preview, but the hosted install code is issued only for a saved widget. Save the widget and open the Publish tab.

3. Paste the code

<div data-popuploom="YOUR_SAVED_WIDGET_ID"></div>
<script src="https://popuploom.com/popuploom.js"></script>

Paste both lines before the closing </body> tag where the platform permits it. Keep the div and the script together. Do not copy the widget id from a preview page; copy the id shown in the Publish tab for the saved popup.

Old installations that use data-popforge and /popforge.js still work. New installations should use the current attributes and the canonical domain.

Platform-specific instructions

  • WordPress — Custom HTML block or theme/footer code, plus script-filtering caveats.
  • Shopify — theme backup, theme code and checkout boundaries.
  • Webflow — site or page custom code and publishing.

4. Test the published page

Use a clean browser session or a private window, visit a page included by your page rules, and perform the chosen trigger. Check desktop and mobile. The studio preview silences trigger timing, so a successful preview does not prove the published trigger works.

For forms, submit one test response and confirm it appears in My popups → Leads. Do not use a real customer's data for the test. If the form appears but the response does not, check the browser console and the lead inbox before changing the design.

What runs natively

  • Popup rendering, placement, triggers, page/device targeting and frequency rules.
  • Hosted lead storage for saved widgets and the authenticated lead inbox.
  • CSV export and JSON configuration backup.
  • Optional browser webhooks and signed server-side webhooks. Delivery is best effort or retried background delivery, not a durable message queue.

Not included natively: marketing email, SMS, PDF delivery, calendar invitations, payment processing, loyalty ledgers, live stock monitoring, price monitoring or verified age identity checks. Age gates are self-declaration controls, not identity verification or legal-compliance certification. Those integrations require the website owner's own tools and honest copy.

Updating or removing the popup

To update, edit and save the same widget. The snippet stays the same. To remove the popup from one site, delete the two-line snippet from that site. To remove the hosted widget and its leads, delete the saved popup from My popups after exporting anything you need.

If it does not appear

Work through the diagnostic guide: confirm the snippet, saved id, trigger, page rules, device rules, frequency, selector, content security policy, cache and iframe support. Do not hide the document or force clicks to make a test pass.

Data and visitor experience

Ask only for the information you need, explain why you collect it, and provide appropriate privacy information. Browser webhook URLs are public in the widget configuration; never put credentials in them. Server-side webhook secrets are owner-only. Avoid covering essential navigation or using a popup where the visitor cannot close it.
