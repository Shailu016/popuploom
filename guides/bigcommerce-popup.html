BigCommerce gives you two routes: Script Manager, which needs no theme edit, and a Stencil theme change, which does. This guide covers both and states the checkout boundary up front. It was checked against BigCommerce's documentation, not tested on a live store.

The checkout boundary. BigCommerce's optimized checkout is separate from the storefront theme, and Script Manager scripts target the storefront. Do not plan a storefront popup on the payment step. If you need a message there, use the checkout's own supported customisation.

Script Manager (recommended)

  1. In the control panel, open Storefront → Script Manager.
  2. Choose Create a Script.
  3. Name it something recognisable, such as “PopupLoom widget”.
  4. Set Location on page to Footer.
  5. Select the pages where it should run. “All pages” is fine if the popup's own URL rule handles targeting; otherwise choose the specific pages.
  6. Set the script type to Script and paste both lines:
<div data-popuploom="YOUR_WIDGET_ID"></div>
<script src="https://popuploom.com/embed/1.1.0/popuploom.js"></script>

Save, then load the storefront in a private window. Script Manager changes can take a moment to appear; if the page is cached, purge it or test with a query string.

Stencil theme edit (advanced)

If you already work with the Stencil CLI and keep the theme in version control, add the same two lines to templates/components/footer.html before the closing body markup, then push the theme. Keep a backup and test on a theme preview before applying it to the live store.

A theme edit disappears if the theme is replaced or reset. Script Manager survives a theme change, which is why it is the safer default for a third-party widget.

Two layers again: Script Manager decides where the widget is loaded, and the popup rule decides where it appears. If the popup never shows on product pages, check both before changing the template.

Multi-storefront stores

A Script Manager entry belongs to a storefront. If the store runs more than one, confirm the script is assigned to the storefront you are testing. “It works on staging but not live” is often this, not a caching problem.

Test checklist

  • Storefront in a private window, popup appears once.
  • Product, category and cart pages behave as configured.
  • Checkout is clean: no overlay, no console errors from the widget.
  • Test submission arrives in the lead inbox.
  • Mobile width and a cached page both work.

Removal

Delete the Script Manager entry, or revert the footer change and push the theme. The saved popup remains in the studio.

Common questions

Will the popup appear on the BigCommerce checkout?

Assume no. The optimized checkout runs separately from the storefront theme and Script Manager scripts. Test the real checkout; if you need a message there, use the checkout's own supported customisation rather than a storefront popup.

Should I use Script Manager or edit the theme?

Script Manager for a change you can add and remove without touching theme files. Edit the Stencil theme only if you already work with the CLI and a version-controlled fork. A script added to the theme disappears if the theme is replaced.

Where should the script be placed in Script Manager?

Footer, on the pages where the popup should load. The footer placement keeps the popup from blocking the storefront's own content, and the page selection keeps it off account or checkout-adjacent routes.

Why does the popup appear in one storefront but not another?

BigCommerce supports multiple storefronts, and a Script Manager entry is scoped to one of them. Check that the script is assigned to the storefront you are testing, not only to the default.
