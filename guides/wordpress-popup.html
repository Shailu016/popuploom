A popup in WordPress does not require a popup plugin. You can build the popup once in PopupLoom, paste two lines into your theme footer or a single Custom HTML block, and keep the design editable from the hosted studio. This page covers the three practical ways to do it, what breaks most often, and when a plugin is genuinely the better choice.

Popup in WordPress: the short version

  1. Create and save the popup in the PopupLoom studio.
  2. Copy the two-line install code from Publish.
  3. Paste it before </body> in a child theme, in a code-snippet plugin, or in a Custom HTML block on one page.
  4. Purge every cache layer and test the published URL in a private window.

That is the whole integration. There is no WordPress plugin to install, no database table to create, and no per-pageview fee. The popup configuration stays on PopupLoom's side, so you can change the offer or design later without editing the WordPress site again.

Why not just install a popup plugin?

A dedicated popup plugin can be the right answer in some cases, but it is not the default. The trade-offs are real:

  • Weight. A plugin loads PHP, admin assets and often a front-end builder on every request. A hosted snippet is two small elements and one script.
  • Lock-in. Designs stored inside a plugin are harder to move. A hosted configuration is independent of the WordPress theme.
  • Maintenance. Every plugin adds update, compatibility and security surface. Fewer plugins is usually better for a site you do not actively maintain.
  • Cost. Many popup plugins gate exit intent, targeting or view volume behind a paid tier. PopupLoom has no pageview cap and no paid upgrade inside the product.

A plugin may still be better if you cannot edit theme code, your host blocks scripts, or a client needs every change made from the WordPress admin. In those cases, use a plugin — just choose it deliberately rather than by default.

Before you start

  • You need permission to add custom HTML or edit theme code. On a client site, confirm that before touching anything.
  • Your WordPress role needs the unfiltered_html capability for script tags. The official block documentation says users without it have their block content sanitized by wp_kses(), which strips disallowed tags such as <script> and <iframe>.
  • Some managed WordPress hosts, security plugins and caching layers also remove or delay scripts. Confirm on staging before promising a client that the popup will run.
  • Back up the site, or work on a staging copy. Do not paste code into a live theme you cannot restore.

Step 1: Save the popup and copy its code

Create the design in the PopupLoom studio. Sign in, save the widget, and open Publish. Copy the two lines that contain the saved widget id and popuploom.js. The full model is in the installation guide. Guest previews do not issue hosted code.

Step 2: Add it with a Custom HTML block

Use this for a single page, post or landing page.

  1. Open the page or post in the WordPress block editor.
  2. Add a Custom HTML block. The official documentation describes searching for “Custom HTML” in the block inserter.
  3. Paste the two PopupLoom lines into the HTML field.
  4. Use the block preview to check that the markup is present. Do not type the angle brackets as visible text in a Paragraph block.
  5. Update or publish the page, then open the published URL in a private window.

If the script disappears after saving, your role probably lacks unfiltered_html, or a security plugin filtered it. Move to a footer-code method instead of fighting the sanitizer.

Step 3: Or add it once in footer code

Use this when the popup should appear across the site. Add the two lines before the closing </body> tag in a child theme's footer template, or through a code-snippet plugin that explicitly allows JavaScript. Do not edit the parent theme directly; a theme update can remove the change.

If your theme does not have a footer.php, or you use a block theme, add the snippet through a code-snippet plugin that injects before the closing body tag. That is still not a popup plugin: it is a paste box for the same two lines.

Keep the widget div and script together. If you paste only the script, no popup is mounted. If you paste only the div, nothing loads the runtime.

Step 4: Clear caches and test

  • Purge the page cache, object cache, CDN cache and any optimization-plugin cache.
  • Open a private window and a logged-out session. Do not test while signed in as an administrator if your caching or script rules differ for administrators.
  • Perform the actual trigger: load, delay, scroll depth, click, scroll-to element or desktop exit intent.
  • Check the browser console for blocked requests or CSP errors.
  • Submit one test form response and confirm it appears in the PopupLoom lead inbox. Use fake data.

Common WordPress problems

  • The block shows the words “Custom HTML” or the code as text. The editor may have escaped the markup. Use the HTML view of the block, not a paragraph.
  • The script is missing from the published page. Check unfiltered_html, security plugins, and host-level script filtering.
  • The popup appears once and never again. Check the frequency setting and whether a page cache is serving an old configuration. Frequency is stored in the visitor's browser.
  • Desktop exit intent does not fire on mobile. Exit intent is desktop only by design. Use a delay, scroll or click trigger for mobile.
  • Nothing renders inside the editor preview. The block preview is not the published site. Test the published URL.
  • A plugin update breaks it. Security and optimization plugins change how scripts are combined or deferred. Re-check the published source after major plugin updates.

Removing the popup

Delete the Custom HTML block from the page, or remove the two lines from the footer code, then purge caches. Deleting the hosted widget in My popups disables the configuration; removing only the snippet removes it from that WordPress site.

WordPress popup FAQ

How do I add a popup in WordPress for free?

Build it in PopupLoom, save it, copy the two-line install code, and paste it into a Custom HTML block or your theme footer. There is no per-view charge. You still need permission to add custom HTML or edit theme code.

Do I need a popup plugin?

No. A plugin is optional. A footer snippet or one Custom HTML block is enough. A code-snippet plugin is only a paste box for the same two lines; it is not required if you can edit a child theme.

Why is my WordPress popup not showing?

Check the published page source first. If the script is missing, the cause is usually unfiltered_html, a security plugin or a host filter. If the script is present, check caching, the frequency rule, the trigger type and the browser console.

Will this work with a block theme?

Yes, if you can inject the snippet before the closing body tag. Block themes use the Site Editor, so a code-snippet plugin or a child theme is usually simpler than editing a block template directly.

Does it work in the editor preview?

Usually not. Scripts are often stripped in the editor and block preview. Test the published URL in a private window.

Can I show it on only one page?

Yes. Use a Custom HTML block on that page instead of site-wide footer code. Keep the div and script together.
