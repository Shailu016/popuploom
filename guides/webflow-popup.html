Add a PopupLoom popup to Webflow

Checked against Webflow's official custom-code documentation on 5 November 2026. This guide was not tested on a live Webflow site; custom-code availability depends on your plan, and the Designer preview does not always execute published code.

Before you start

  • Confirm that your Webflow plan permits custom code. Webflow's official documentation covers where custom code can be added; plan and site permissions still control whether it runs.
  • Use a duplicate or staging site when possible. Custom code is an advanced change and Webflow warns that it can conflict with site functionality.
  • Decide whether the popup should appear on every page (site-wide footer code) or only one page (page-level code).
  • Custom code fields have a character limit; Webflow's current documentation states 50,000 characters per field. The PopupLoom snippet is much smaller, so this is not normally a concern.

Step 1: Save the popup and copy its code

Build and save the popup in the PopupLoom studio, open Publish, and copy the two-line install pair. The general model is in the installation guide. Guest previews do not issue hosted code.

Step 2: Add site-wide footer code

  1. Open the Webflow project and go to Project settings → Custom code.
  2. Find the Footer code field, which Webflow places before the closing </body> tag.
  3. Paste the PopupLoom div and script.
  4. Save the changes.
  5. Publish the site. Custom code typically requires publishing; the Designer canvas may not run it.

Step 3: Or add page-level code

For a single page, open the page settings and use the custom code section for code before </body>. Keep the widget div and script together. Page-level code is useful for a launch page or a single campaign.

Step 4: Test the published site

  • Open the published domain in a private window, not the Designer preview.
  • View the page source and confirm the widget div and script are present.
  • Perform the actual trigger and test a form response with fake data.
  • Check the browser console for blocked resources or CSP errors.
  • Test a small viewport. Webflow's responsive breakpoints can hide elements or alter the page height; confirm the popup can still be closed and does not cover navigation.

Webflow-specific problems

  • The code works in preview but not on the live site. Publish the site and verify custom code is enabled for the published domain.
  • Nothing appears in the Designer. That can be expected. Test the published URL.
  • An HTML Embed is used instead of footer code. Webflow's embed element may be placed inside a layout container; a fixed-position popup can be clipped by an ancestor with overflow hidden. Site-wide footer code is the more predictable path.
  • A plan change disables custom code. Check the current plan permissions before relying on the popup for a campaign.
  • A Content Security Policy blocks the script. Allowlist the PopupLoom runtime origin; do not remove the policy globally.

Removing the popup

Remove the two lines from the site or page custom-code field, save, and publish again. Delete or disable the hosted widget separately if you no longer want its configuration available.
