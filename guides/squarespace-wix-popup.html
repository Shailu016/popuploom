Add a popup to Squarespace or Wix without an app

By Shailu, founder of PopupLoom · Last updated 16 November 2026

Checked against Squarespace and Wix official documentation on 12 November 2026. This guide was not tested on a live Squarespace or Wix site; plan names, permissions and editor behavior change, so verify on your own site before a campaign.

Both platforms can run a free PopupLoom popup, but the gate is the plan, not the popup. Squarespace puts code injection behind Core and higher. Wix puts custom code behind a published site with a connected domain, and a custom domain generally requires a Premium plan. Once you clear that gate, the install is two lines in a footer field.

Before you start

  • Confirm that your current plan includes the code feature. On Squarespace, look for the Code Injection panel; on Wix, look for Custom Code under Development & integrations.
  • Save or duplicate the site first. Custom code can affect layout and behavior, and neither platform's support team will debug third-party code.
  • Decide scope: all pages for a site-wide welcome popup, or one page for a launch.
  • Have the two-line install code ready from PopupLoom's Publish screen. The general model is in the installation guide.

Squarespace: add the popup with code injection

  1. Open the site dashboard and go to Settings → Advanced → Code Injection.
  2. Put the PopupLoom widget div and script in the Footer field. Squarespace injects footer code before the closing body tag, which is where the widget expects to mount.
  3. Save the change.
  4. Open the published domain in a private window. Code injection is not a preview feature; test the live page.
  5. Perform the real trigger and submit one test form response with fake data.

For a single page, use the page's own code injection field instead of the site-wide footer. Do not put the script in a Code Block on the Basic plan: Squarespace documents JavaScript and iframes in code blocks as requiring Core or higher, and a Code Block can be clipped by a parent container.

Squarespace limits to plan around

  • Checkout is excluded. Squarespace's documentation says checkout pages do not support code. Do not promise a post-purchase or checkout popup from this install.
  • Code injection is plan-gated. Core, Plus, Advanced and some legacy plans include it; Basic does not.
  • Support boundary. Squarespace support will not troubleshoot custom code. Keep the snippet and a rollback note.

Wix: add the popup with custom code

  1. Publish the site and connect its domain first. Wix's documentation lists those as prerequisites for custom code.
  2. In the site dashboard, open Settings → Custom Code under Development & integrations.
  3. Choose Add Custom Code, paste the two PopupLoom lines, and give the snippet a recognisable name.
  4. Under Add Code to Pages, choose all pages or specific pages. For a site-wide welcome popup, choose all pages and load it once per visit unless you have a reason not to.
  5. Under Place Code in, choose Body – end.
  6. Apply, then publish the site again if Wix asks you to.
  7. Open the published domain in a private window and test the trigger.

Wix limits to plan around

  • No access to Wix APIs. Wix's documentation says custom code works with the raw DOM and external resources, not Wix data collections, Stores, Bookings or member data. PopupLoom cannot read your Wix catalog or cart.
  • Dynamic DOM. Wix generates class names and element IDs at runtime. Do not build the popup around Wix selectors; use PopupLoom's URL and device targeting instead.
  • No editor preview. Custom code runs on the published site, not inside the editor.
  • Third-party support boundary. Wix says to contact the code provider for issues. That is us for the popup snippet, not for your Wix theme.

Test the popup properly

  • Use a private window and a logged-out session.
  • Confirm the widget div and script are in the published page source.
  • Trigger the real behavior: page load, delay, scroll, click or desktop exit intent.
  • Submit one fake lead and confirm it appears in the lead inbox.
  • Check mobile separately. Exit intent is desktop only by design.
  • Check the browser console for blocked scripts or a Content Security Policy error.

When a platform-specific app is the better choice

Use a Squarespace or Wix app if you need to branch on platform data: cart value, specific products, member fields, CMS collections, native discount logic, A/B testing or checkout messages. PopupLoom cannot read those. Use PopupLoom when you need a free, lightweight popup for the storefront with URL and device targeting, timed or exit-intent triggers, lead capture and CSV export.

Squarespace and Wix popup FAQ

Can I add a free popup to Squarespace?

Yes, if your plan includes code injection. Add the snippet to the footer code injection field and test the published site. Checkout pages do not support code.

Can I add a popup to Wix without an app?

Yes, on sites that can use custom code. Publish the site, connect the domain, then add the snippet under Settings → Custom Code → Body – end.

Why is the Wix popup not showing?

Test the published site, not the editor. Check that the code is applied to the right pages, placed in the body end, saved, and that the site is published on the connected domain.

Does it work on Squarespace checkout?

No. Squarespace documents that checkout pages do not support code.

Is it cheaper than a popup app?

PopupLoom is free with no pageview cap. You still pay for the website platform. A dedicated app may be worth it for platform-specific cart or CMS data.
