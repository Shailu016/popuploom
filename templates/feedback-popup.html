A feedback popup asks one question and offers a small number of tappable answers. The Tap Meter template shows three faces and a one-line question in a bottom-right card. There is no email field and no submit button: the visitor taps once, the answer is saved, and the card thanks them.

This page covers when a one-tap prompt is worth showing, how the response is stored, the frequency that keeps it from becoming noise, and what the numbers can and cannot tell you. It is one of the engagement templates, which also covers referral, review and loyalty layouts.

A feedback prompt is not a survey platform. PopupLoom stores the chosen value and the time it was submitted. It does not run branching logic, score sentiment, send a follow-up email or stop the same person answering twice from a second browser.

What this template is for

The prompt is designed for a page that has already delivered something: an article, a pricing page, a help article or a checkout confirmation. The visitor is not being asked to buy; they are being asked whether the page worked.

  • A mood check on a content or help page: great, meh or rough.
  • A micro-commitment before a larger ask, using the same choice mechanic.
  • A post-order pulse that routes happy customers toward a review and unhappy ones toward support.
  • A lightweight signal for a small site that will actually read the answers.

It is not a replacement for a support form, a bug tracker or a research panel. If the answer needs a reply, collect a contact address and say who will respond.

Why one tap beats a form

Every additional field is a reason to close the card. A three-choice prompt asks for a decision the visitor can make in a second, so the completion rate is usually higher than a star rating followed by a comment box. The trade is depth: you learn the direction of the experience, not the reason behind it.

That is enough for triage. A run of “rough” answers on one page tells you where to look. It does not tell you which sentence confused the reader, so pair the prompt with a link to a real contact route for anyone who wants to explain.

Use it when

  • You will read the responses and change something.
  • The page has a clear end point, so the prompt is not competing with the main action.
  • You can set a frequency that does not repeat on every page view.
  • The wording is neutral enough that “rough” is a safe answer.

Do not show it on checkout, in the middle of a form, or on every article a reader opens. Do not use it to collect marketing consent; a mood check is not an opt-in.

Copy you can adapt

Badge: 10-second check

Question: How is this page landing?

Choices: Great · Meh · Rough

Small print: Answers are read, not published. Need a reply? Contact us.

Keep the choices about the page, not the person. “Rough” is easier to tap than “terrible”, and it is easier to act on. If you name a follow-up channel, make sure someone monitors it. The copy swipe file has more one-line prompt patterns.

Set it up

  1. Open the Tap Meter template in the studio.
  2. Edit the question and the three labels. Keep each label to one or two words.
  3. Leave the form off. The choice buttons submit on their own.
  4. Set the trigger to Scroll depth and start at 65%. Adjust after a week if the prompt appears before the page is useful.
  5. Set the frequency to once per week and restrict the URL rules to the pages you want to learn about.
  6. Save, publish and paste the install snippet using the installation guide.
  7. Open the lead inbox and confirm a test answer appears with the choice value.

Where the answers go

Each tap creates a response in the popup's lead inbox with a choice field, for example great. The inbox shows the value and the submission time, and the CSV export includes it alongside any other fields you add. The response does not include a name or email address unless you add fields for them.

The dashboard also counts de-duplicated popup views. Divide responses by views for a rough response rate, but treat it as a product counter rather than an analytics report: it is not segmented by page, device or traffic source, and a visitor who blocks the script is not counted at all.

What to measure

  • Response mix over time. A shift from “great” to “rough” on one page is the signal worth chasing.
  • Response rate by page, using separate popups if you need the split.
  • What you changed after reading the answers. A prompt nobody acts on is decoration.
  • Dismissal and complaint feedback. If people mention the prompt itself, it is too frequent.

Do not report a response rate as a conversion rate. The prompt measures opinion, not revenue, and the sample is self-selected.

Common mistakes

  • Turning a one-question prompt into a five-field survey.
  • Asking for feedback and never following up.
  • Showing the prompt on every page view until it is dismissed by reflex.
  • Using leading choices such as “Amazing” and “Okay” that make one answer socially safer.
  • Treating a handful of taps as a representative sample of all visitors.
  • Collecting an email without saying what it will be used for.

Common questions

Are the feedback answers stored?

Yes. Tapping a choice records a response with a choice field, such as great, meh or rough. The response appears in the lead inbox for that popup and is included in the CSV export. No email address is collected by this template.

Can I add a comment box?

Yes. Add a form field in the studio, but understand the trade: a one-tap prompt gets more responses than a prompt that also asks for text. Ask for a comment only after the visitor has chosen an answer.

Does PopupLoom show a response rate?

The dashboard counts de-duplicated popup views and the lead inbox counts stored responses, so you can divide one by the other. The view count is a product counter, not an analytics platform, and it does not break down by page or device.

Will the popup follow the visitor around the site?

Only if you set it to. The template's default frequency is once per visitor per week and it is limited to the page rules you choose. Repeating a feedback prompt on every page view is the fastest way to get dismissed without an answer.
