A cart rescue popup appears when a shopper is about to leave the cart page. It offers a reason to finish the order — a discount, a shipping reminder or a support link — without interrupting people who are still browsing. The layout is a small card with one offer, one action and an obvious close button.

This page covers the trigger configuration, the URL rules that keep it off checkout, the copy to adapt and the things that go wrong. It is one of the exit-intent templates, and it uses the same desktop-only exit trigger as the rest of that category.

What this template is for

The cart page is the highest-intent moment in a store. The visitor has chosen something and stopped. The popup's job is not to argue; it is to remove one specific reason to leave. That is why the layout keeps one field, one button and one line of small print.

  • One offer. A discount, free shipping or a saved-cart reminder. Two offers read as a sale, not a rescue.
  • One action. The button returns the visitor to the cart or reveals a code; it does not open a second form.
  • One dismissal. A visible close button, a backdrop click and Escape all work.
  • No cart totals. PopupLoom cannot read the cart value, so the copy must not promise “10% off your $84 order”.

Use it when

  • The visitor is on the cart page and has not started checkout.
  • You have a real reason to offer: a first-order code, a shipping threshold or a way to save the cart.
  • You can afford the discount on the margin. A rescue that loses money is not a rescue.
  • You have a separate mobile plan, because the desktop trigger will not fire on phones.

Do not use it on checkout, on the order confirmation page or immediately after an add-to-cart. Those pages have their own jobs, and an overlay there is an interruption rather than a save.

Copy you can adapt

Badge: BEFORE YOU GO

Headline: Your cart is still here

Subheadline: Finish the order, or take [X]% off if that is the sticking point.

Button: Back to my cart

Small print: One use per customer. Code expires [DATE].

Replace every bracket. If the code is not real, remove the discount sentence rather than inventing a number. The copy generator produces twelve more cart-recovery variants if you want to compare structures.

Set it up

  1. Open the Cart Rescue template in the studio.
  2. Replace the headline, subheadline and small print. Set the button to return to the cart or reveal the code.
  3. Set the trigger to Exit intent. Do not add a timer to the same popup; pick one.
  4. Add the URL rule: include /cart*, exclude /checkout* and /order*.
  5. Save, publish and paste the two-line snippet. The installation guide covers placement and caching.
  6. Create a second popup for mobile with a scroll or delay trigger.
  7. Test on a desktop: load the cart, wait past the grace period, move the pointer up. Then test that checkout is clean.

What to measure

  • Cart completions before and after over a comparable period, not a single day.
  • Discount cost against the margin on the orders it saves. A rescue that converts at a loss is not working.
  • Dismissal rate. A popup that is closed instantly is usually mistimed or repeating.
  • Checkout leakage. If completions fall after launch, check that the popup is not appearing on checkout.

PopupLoom has no built-in analytics for popups. Use your store's reporting for orders and your own event tracking for impressions if you need them.

Common mistakes

  • Showing the popup on checkout because the URL rule was left as “all pages”.
  • Promising a cart-specific value the popup cannot read.
  • Using a countdown that resets on reload, which teaches visitors to distrust every timer.
  • Forgetting the mobile companion, then concluding that “exit intent does not work” from phone traffic.
  • Making the close button small or low-contrast on a page where the visitor is already trying to leave.

Common questions

Should a cart rescue popup show on checkout?

No. Exclude checkout pages from the URL rule. A visitor who is entering payment details has already decided; an overlay at that step adds friction and can break the flow.

Does exit intent work on mobile for cart rescue?

Exit intent is desktop only. For phones, create a second popup with a scroll-depth or timer trigger, and make the dismiss button large enough to tap without hitting the offer.

Can PopupLoom read my cart total or products?

No. PopupLoom does not inspect native cart totals, customer state or inventory. It targets by URL path and can read a CSS selector on the page, so dynamic cart contents need your own logic or a different tool.

How often should the popup appear?

Once per visitor per cart session is a reasonable starting point. Showing it on every visit teaches people to dismiss it without reading, and a cart that is still open days later is better served by email than by another overlay.
